# 高德企业打车

在 Android Studio AVD 的高德地图中配置、提交和跟踪企业用车。执行图形界面操作时使用 `android-device-automation` 技能；状态读取和安全判断优先使用 `zx` 执行 `scripts/amap_adb.mjs`，不要手工拼接长串 `adb + sleep`。除非用户明确要求，不启动或依赖 MuMu 模拟器。

## AVD 设备

- 默认 AVD：`High_Performance_API_34`。
- 启动前运行 Android SDK 的 `emulator -list-avds`，确认目标 AVD 存在；不存在时停止并向用户说明，不要创建或改用未确认的新设备。
- 使用 Android SDK 的 `emulator -avd High_Performance_API_34` 启动，并等待 `adb shell getprop sys.boot_completed` 返回 `1`。不要把启动中的 `offline` 状态当作失败。
- 设备在线后记录 `adb devices` 返回的序列号。连接多个设备时，对 Midscene 使用 `--device-id <序列号>`，对后备脚本设置 `AMAP_ADB_SERIAL=<序列号>`，不得依赖默认设备选择。
- 启动高德前检查应用包是否已安装；若未安装或登录态缺失，停止并请用户处理，不要从非官方来源安装应用，也不要绕过登录。

## 默认行程

- 用车模式：企业打车 / 企业版
- 起点：根据当天飞书日程选择；没有匹配日程时默认使用桂溪广场 C 栋夜间上车点
- 终点：人居越秀・和樾林语语澜组团（东北门）
- 日期：`Asia/Shanghai` 时区的当天
- 上车时间：21:35
- 车型：专车
- 支付限制：个人支付必须为 0，订单汇总必须显示 `本单为企付`

用户提供的新参数优先于默认值。如果当天 21:35 已经过期，不要擅自改为明天；询问新的日期或时间。

### 根据飞书日程选择起点

用户没有显式指定起点时，在操作高德前运行 `node scripts/check_calendar.mjs`，由脚本通过 `lark-calendar` 的用户身份用 `+agenda` 拉取当天主日历的全天日程。日期和时间边界均按 `Asia/Shanghai` 计算并显式携带 `+08:00`，不要依赖运行环境的默认时区。

预约课日程的标题是课程名（如「燃脂搏击 BODYCOMBAT」「活力蹦床 UP N DOWN®」），门店名在地点字段 `location.name` 中；不要按标题匹配。逐条核对返回结果，只匹配未取消且 `location.name` 完全为 `超级猩猩（天府三街全能店）`、起止都在当天的日程，再按准确的开始和结束时间选择起点：

- 当天 18:40–20:40：起点使用 `桂溪广场 C 栋夜间上车点`。
- 当天 19:50–20:50：起点使用 `肯德基（海洋中心店）`。

如果两种时间的匹配日程在同一天同时存在，停止配置并请用户确认起点，不要自行决定优先级。没有匹配日程时，继续使用默认起点 `桂溪广场 C 栋夜间上车点`。如果日历查询、认证或结果解析失败，不能把失败当作“没有匹配日程”；停止配置并请用户确认当天是否有该日程。用户显式指定的起点始终优先，不被此规则覆盖。

### 工作日定时检查

系统 cron 在 `Asia/Shanghai` 时区的每周一至周五 18:00 运行一次 `scripts/check_calendar.mjs`，将结构化检查结果追加到项目根目录 `.reports/amap-enterprise-ride/calendar-check.log`。定时检查只判断日程和建议起点，不配置或提交订单；实际叫车仍须执行本技能的界面检查和呼叫前确认。

## 配置行程

1. 按“根据飞书日程选择起点”确定本次起点，并记录匹配结果。
2. 按“AVD 设备”启动并确认 AVD 在线，高德地图已安装并完成登录。
3. 打开高德地图并进入企业版/企业打车。不要在个人打车模式中继续。
4. 设置准确的起点和终点。优先选择上述完整名称，拒绝名称相近但楼栋、门或小区不同的地点。
5. 选择预约用车，设置当天 21:35。关闭时间选择器后重新读取页面上的日期和时间。
6. 打开专车分类并展开供应商列表。
7. 选择所有没有 `个人付` 标签的专车供应商。排除所有显示 `个人付 N元` 的选项；即使同一供应商的另一个服务档位可以企付，也不得混淆。
8. 每选择一个或一小批供应商后重新读取界面。选择状态变化可能导致列表移动，不要复用旧坐标。
9. 继续前必须同时满足：
   - 当前车型为专车。
   - 至少选择一家供应商。
   - 底部显示 `本单为企付`，不能显示 `本单含个付`。
   - 路线和预约时间与用户要求完全一致。

使用 `status --json` 读取当前状态；呼叫前使用 `snapshot <前缀>` 原子保存 XML、截图和结构化摘要。价格、数量和支付状态以最新快照为准。

分类上的 `自费升舱` 标签不能证明所有供应商都需要个人支付。必须依据每个供应商行的 `个人付` 标签及订单汇总的 `本单为企付` 判断。

## 呼叫、提交与跟踪

配置完成后、触碰最终呼叫按钮前，必须完整阅读并遵循 [呼叫流程](references/call-flow.md)。呼叫前使用 `lark-card` 技能向 `liutao.fe@bytedance.com` 的已核验私聊发送确认卡片，卡片展示本次行程信息，并提供“确认呼叫”和“拒绝”按钮；收到本次卡片的有效确认后才可继续。该流程还包含个人支付阈值弹窗处理、提交幂等、呼叫后监控、恢复规则和司机接单后的飞书通知。

## ADB 后备工具

在技能目录中运行 `npx --yes zx scripts/amap_adb.mjs help` 查看命令。脚本支持自动重试、快照、离线 XML 解析、结构化状态、阈值安全确认和接单监控。优先使用最新 UI 文本边界，不要依赖硬编码坐标。连接多个安卓设备时设置 `AMAP_ADB_SERIAL`。
