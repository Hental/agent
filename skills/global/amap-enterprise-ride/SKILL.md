# 高德企业打车

在安卓模拟器的高德地图中配置、提交和跟踪企业用车。执行图形界面操作时使用 `computer-use` 技能并遵守其确认策略。如果 macOS 辅助功能无法访问模拟器窗口，使用 `zx` 执行 `scripts/amap_adb.mjs` 作为 ADB 后备方案。优先使用脚本的结构化状态和安全判断命令，不要手工拼接长串 `adb + sleep`。

## 默认行程

- 用车模式：企业打车 / 企业版
- 起点：桂溪广场 C 栋夜间上车点
- 终点：人居越秀・和樾林语语澜组团（东北门）
- 日期：`Asia/Shanghai` 时区的当天
- 上车时间：21:35
- 车型：专车
- 支付限制：个人支付必须为 0，订单汇总必须显示 `本单为企付`

用户提供的新参数优先于默认值。如果当天 21:35 已经过期，不要擅自改为明天；询问新的日期或时间。

## 配置行程

1. 确认安卓模拟器在线，高德地图已安装并完成登录。
2. 打开高德地图并进入企业版/企业打车。不要在个人打车模式中继续。
3. 设置准确的起点和终点。优先选择上述完整名称，拒绝名称相近但楼栋、门或小区不同的地点。
4. 选择预约用车，设置当天 21:35。关闭时间选择器后重新读取页面上的日期和时间。
5. 打开专车分类并展开供应商列表。
6. 选择所有没有 `个人付` 标签的专车供应商。排除所有显示 `个人付 N元` 的选项；即使同一供应商的另一个服务档位可以企付，也不得混淆。
7. 每选择一个或一小批供应商后重新读取界面。选择状态变化可能导致列表移动，不要复用旧坐标。
8. 继续前必须同时满足：
   - 当前车型为专车。
   - 至少选择一家供应商。
   - 底部显示 `本单为企付`，不能显示 `本单含个付`。
   - 路线和预约时间与用户要求完全一致。

使用 `status --json` 读取当前状态；呼叫前使用 `snapshot <前缀>` 原子保存 XML、截图和结构化摘要。价格、数量和支付状态以最新快照为准。

分类上的 `自费升舱` 标签不能证明所有供应商都需要个人支付。必须依据每个供应商行的 `个人付` 标签及订单汇总的 `本单为企付` 判断。

## 呼叫前确认

在最终的 `呼叫N种车型` 按钮前停止，并向用户发送：

- 准确的起点和终点
- 准确的日期和时间
- 车型及已选供应商数量
- 预估价格区间
- 支付状态（`本单为企付`）
- 显示订单汇总和最终按钮的当前截图

询问：`以上信息是否确认？确认后呼叫这 N 种车型。`

没有获得针对当前页面信息的新一次明确确认，不得提交。如果确认后价格、路线、时间、供应商数量或支付状态发生变化，必须停止并重新确认。

确认后遵守当前界面工具的财务操作策略。如果允许代理完成，则只点击一次最终按钮；如果策略要求用户接管，则请用户完成这一次点击，然后恢复监控。在首个订单状态不明确时，绝不能再次提交。点击后立即读取状态；出现加载中、弹窗或未知状态都不代表失败，不得再次点击最终按钮。

## 下单弹窗处理

点击最终呼叫按钮前，记录当前已选车型的预估价格上限 `M` 和用户确认的价格上限。若下单时出现“实际支付金额超出 `T` 元的部分，需要您个人支付”一类弹窗：

1. 从弹窗中读取个人支付阈值 `T`，不要使用历史阈值或猜测数值。
2. 重新读取当前已选车型的预估价格上限 `M`，并确认路线、预约时间、供应商数量和 `本单为企付` 均未变化。
3. 运行 `confirm-threshold <用户确认上限>`。脚本仅在 `M < T`、`M` 不超过用户确认上限且页面仍显示 `本单为企付` 时点击弹窗“确认”。
4. 脚本返回 `stop`、退出码 4、无法解析字段或页面发生变化时，不要手工绕过；停止并向用户确认。

例如：当前已选预估上限为 101 元，弹窗阈值为 106.14 元，因为 `101 < 106.14`，可以自动确认继续。

## 呼叫后监控

1. 确认页面已从呼叫前状态切换到正在派单、搜索司机或活动订单。
2. 运行 `monitor --interval 15 --timeout 900 --prefix <截图前缀>`，或大约每 15 秒读取一次订单状态。仍在搜索时，至少每分钟向用户更新一次。
3. 司机接单、派单失败、用户取消或应用要求作出重要选择时停止轮询。
4. 司机接单后立即发送：
   - 供应商/平台
   - 页面显示的司机姓名
   - 车辆颜色、品牌和型号
   - 完整车牌号
   - 司机预计到达时间/距离
   - 已确认的上车点和预约时间
   - 当前截图
5. 无法读取的字段明确标记为“暂不可用”，不得猜测车牌或司机身份。

修改行程、接受付费升舱、实际增加个人支付或取消活动订单前，必须询问用户。仅当下单弹窗满足上述 `M < T` 规则时，可以自动确认阈值提示。

## 恢复与幂等

- 设备离线时先恢复连接，再读取当前页面；不要把 ADB 失败当作下单失败。
- 应用重启后先检查活动订单。看到预约成功、司机、车牌或取消行程入口时，直接进入监控，禁止重新配置和提交。
- 仅当最新结构化状态明确为 `pre_call` 且不存在活动订单时，才允许执行最终呼叫。
- 使用 `tap-text <文本> --timeout <秒>` 等待异步页面；不要复用旧 XML 坐标。

## ADB 后备工具

在技能目录中运行 `npx --yes zx scripts/amap_adb.mjs help` 查看命令。脚本支持自动重试、快照、离线 XML 解析、结构化状态、阈值安全确认和接单监控。优先使用最新 UI 文本边界，不要依赖硬编码坐标。连接多个安卓设备时设置 `AMAP_ADB_SERIAL`。
