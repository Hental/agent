## 4 四个代表项目的写作顺序

每个项目使用“业务问题 → 本人责任 → 技术决策 → 结果 → 口径”结构。简历中通常压缩为 2—4 条，面试时再展开。

### 互动白板

- 问题：跨端重复维护、实时同步延迟、多人状态一致性与 SDK 质量。
- 责任：项目 Owner，整体技术设计与能力建设；主导跨端迁移。
- 决策：Canvas 2D、RTS 与 Protobuf；元素锁和一致性检测；快照回放；WebView 与通用 Hybrid 调用协议；转码预处理与重试。
- 结果：延迟 600ms → 100ms；覆盖率 0 → 74%；千行 Bug 率 30+ → 1 以下；单需求 Native 人力投入 3 → 0.5。
- 边界：单需求“人力”不改写为“人天”；白板用量包含测试，未放入核心成果。

### 跨端 SDK 自动生成

- 问题：React Native SDK 大量 API 封装重复、交付成本高。
- 责任：建设 Native API 信息提取、TypeScript 代码生成和运行时调用链路。
- 决策：Doxygen 二次开发 → 结构化 API → TypeScript SDK → IPC → Native 反射调用。
- 结果：拉流 69 API，45 预估人天 → 13 人天；推流 242 API，50 预估人天 → 19 人天。
- 边界：对照值是人工方案预估，不能写成两次实测耗时对比。

### 交易研发资产

- 问题：多行业、多场景 UI 难以复现，截图、接口、业务身份和代码难以关联。
- 责任：截图采集、运行时卡片标识、接口与后端对接、截图质量和覆盖率优化。
- 决策：DitoM 插件集成真机同步、接口抓取、Mock、任意门；通过运行时标注采集卡片关系。
- 结果：2026 Q2 团队资产准确率 81.81% → 92.31%，场景与 UI 覆盖率 38.71% → 58%。
- 边界：团队指标、内部试用阶段；代码图谱和知识库主要由同事负责。

### 商业化移动端编辑器

- 问题：中小广告主需要便捷制作移动端落地页。
- 责任：编辑器设计与开发，贯通模板、组件、BFF 和渲染。
- 结果：DOU+ 落地，日均有消耗站点 87 个、日均广告消耗 1.7 万+、管理模板 300+。
- 边界：投放规模不能写作新增营收；原材料未注明消耗币种和精确统计窗口。

## 5 两页内容安排
