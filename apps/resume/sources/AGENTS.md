# 项目资料归档

目录格式为 `<两位序号>_<团队>_<project-id>/`，序号按报告代表项目的展示顺序（时间降序）排列。`project-id` 与 `../data/resume.json` 一致，目录改名不改变项目 ID。

| 目录 | 项目 |
| --- | --- |
| `01_生活服务_order-e2e/` | 订单 E2E 自动化 |
| `02_生活服务_assets/` | 交易研发资产 |
| `03_视频云_sdk/` | 跨端 SDK 自动生成 |
| `04_视频云_board/` | 互动白板 |
| `05_商业化_editor/` | 移动端落地页编辑器 |

## 文件约定

- `meta.json`：项目 ID、序号（`order`）、团队（`team`）、标题、时间、角色、报告正文映射及材料清单。
- `project.md`：项目资料入口，指向 `../../data/<项目目录>/` 中的事实文档。旧整理快照已替换为入口，避免把旧简历结论当成原始证据。
- 其他 `.md`：原文快照、消息摘录或代码阅读摘要；由 `materials[].kind` 区分。同一材料涉及多个项目时，必须引用同一个文件，禁止复制。

`materials[].file` 相对于当前项目目录；`report` 中的文件路径也相对于当前项目目录。`copied_from`（非空时）记录归档时相对于工作区根目录的来源路径，仅用于追溯；读取归档资料不依赖该路径继续存在。`sha256` 校验完整文件，`content_sha256` 校验去除元信息后的正文；更新元信息后同步校验值及引用行号。`source_ids` 对应报告 JSON 的来源 ID。

## 维护规则

- 禁止重复 Markdown：相同正文只保留一份，跨项目通过相对路径引用；去重前核对正文一致，并同步索引和元信息。
- 文档原文正文保持不变；允许添加或更新文件头元信息。项目归纳放在 `data/<项目目录>/`，不在 sources 内维护第二套结论。
- 消息只保留与项目直接相关的内容、时间、发送者、会话和消息 ID、原消息链接；不要归档整批无关聊天记录。
- 明确区分目标与达成、估算与实测、个人与团队成果，以及历史状态与当前状态。
- 渲染入口仍是 `../data/resume.md` 与 `../data/resume.json`；本次目录整理不改变 HTML/PDF 构建流程。报告内容更新时同步 `data/<项目目录>/` 内的项目事实和 `evidence.json`；不再在 sources 中复制报告结论。
- 搜索响应、调试日志及资源预览放在工作区根目录 `.reports/`；仅将选定的最终项目资料归档到这里。

## 阅读入口与补充材料

- `INDEX.md`：按项目组织的来源阅读入口。
- `catalog.json`：原始快照、外部 URL、材料类型与 SHA-256。
- 后续补充的来源直接归入对应项目目录；跨项目的个人总结等归入 `00_公共资料/`，不按检索批次另建目录。检索响应继续留在 `.reports/`。
- `data/<项目目录>/user-confirmed.md` 单独保存用户补充，不能将其伪装为来源原文。
- 原始材料只保留必要快照，不批量创建可读副本；项目归纳统一放在 `data/<项目目录>/`，索引直接引用快照。

## Markdown 元信息（必填）

每个 `.md` 必须以 YAML front matter 开头，包含 `source`、`source_title`、`type`、`summary`：

```yaml
---
source:
  - "原始文档 URL 或相对于本文件的来源路径"
source_title: "《飞书文档标题》"
type: "document_snapshot"
summary: "说明材料包含什么，以及必要的证据限制。"
---
```

- `source`：来源列表；多份来源逐项列出。同一来源的多个项目引用不能复制为多个文件。无法确定来源时先核实，不编造链接。
- `source_title`：保留飞书原始标题，格式为 `《标题》`，不得用本地简称替代；多个来源按 `source` 顺序用分号列出。非飞书材料填写实际来源名称，不冒充飞书文档。标题不清楚时查询核实。
- `type`：使用 `document_snapshot`（文档原文）、`meeting_summary`（会议纪要）、`message_excerpt`（消息摘录）、`code_reading_summary`（代码阅读摘要）、`historical_summary`（历史整理）、`index`（索引）或 `instructions`（维护规则）。
- `summary`：忠实说明材料范围；不增加原文未支持的结果、归属或结论。历史整理和智能纪要明确其限制。
- 去重比较正文，忽略元信息和换行差异；不能通过不同标题、来源 ID 或元信息绕过检查。同源不同内容先核对版本，确需保留时在摘要中说明版本差异。
- 修改后检查：全部 Markdown 元信息齐全、无重复正文、本地引用有效、catalog 和项目 meta 校验值一致、事实摘录的行号有效。
