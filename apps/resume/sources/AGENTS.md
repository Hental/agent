# 项目资料归档

每个代表项目使用与 `../data/report.json` 一致的项目 ID 建目录：

| 目录 | 项目 |
| --- | --- |
| `order-e2e/` | 订单 E2E 自动化 |
| `assets/` | 交易研发资产与场景复现 |
| `sdk/` | 跨端 SDK 自动生成 |
| `board/` | 火山互动白板 |
| `editor/` | 商业化移动端落地页编辑器 |

## 文件约定

- `meta.json`：项目 ID、标题、时间、角色、报告正文映射及材料清单。
- `project.md`：项目简介（时间、背景、问题）、个人职责、技术介绍、项目结果与收益、证据口径。它是报告内容的整理快照，不是独立原始证据。
- 其他 `.md`：原文快照、消息摘录或代码阅读摘要；由 `materials[].kind` 区分。一个来源涉及多个项目时，各目录可保存完整副本。

`materials[].file` 相对于当前项目目录；`report` 中的文件路径也相对于当前项目目录。`copied_from`（非空时）记录归档时相对于工作区根目录的来源路径，仅用于追溯；读取归档资料不依赖该路径继续存在。`sha256` 校验归档文件内容；更新材料后同步更新哈希及来源信息。`source_ids` 对应报告 JSON 的来源 ID。

## 维护规则

- 保留本目录根层原始 Markdown 和搜索 JSON，不删除、不改写；项目目录是新增的组织视图。
- 文档原文副本保持不变；摘要、消息摘录与代码阅读结论另存，并标明来源、日期与证据限制。
- 消息只保留与项目直接相关的内容、时间、发送者、会话和消息 ID、原消息链接；不要归档整批无关聊天记录。
- 明确区分目标与达成、估算与实测、个人与团队成果，以及历史状态与当前状态。
- 渲染入口仍是 `../data/report.md` 与 `../data/report.json`；本次目录整理不改变 HTML/PDF 构建流程。报告内容更新后，需要同步对应的 `project.md` 快照与元信息。
- 搜索响应、调试日志及资源预览放在工作区根目录 `.reports/`；仅将选定的最终项目资料归档到这里。
