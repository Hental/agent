### 一、2025年度贡献回顾

2025年是聚焦于研发提效和业务深入支持的一年。本年度的工作核心在于主导并从零到一构建了服务于本地生活业务的研发提效平台（`ies/poi-zetton`），同时深度参与到家旅等业务（`life_service/life_trip_c_mono`）的日常迭代与稳定性维护中。
**核心贡献**可以概括为以下两点：
1. **研发提效平台建设**：为提升本地生活前端研发团队的开发与调试效率，独立设计并开发了 `poi-zetton` 平台。该平台围绕“资产标准化”和“调试便利化”两大核心理念，实现了包括“资产上翻”、“Anywhere 任意门调试”在内的多项创新功能，有效缩短了从开发到验证的链路，降低了多环境、多场景下的调试成本。
1. **业务支撑与深度参与**：紧密配合业务需求，完成了酒旅、到餐等多个业务场景的功能迭代和体验优化。通过对现有代码架构的梳理和重构，解决了多个历史遗留问题，保证了业务的稳定运行，并能快速响应业务变化。

总体而言，全年的工作不仅局限于完成业务交付，更通过平台化的方式，为团队的长期研发效率和质量带来了结构性的提升。

### 二、方向及重点事项剖析

本年度的工作主要围绕以下两个方向展开：
#### **方向一：研发提效平台（poi-zetton）从 0 到 1 建设**

> [!TIP]
> `poi-zetton` 是一个为本地生活前端开发者设计的研发提效中台。面对业务场景复杂、开发/调试环境多样、线上问题排查链路长等痛点，该平台旨在通过提供一系列标准化、自动化的工具集，降低研发心智负担，提升交付效率与质量。
>
**1. 重点事项：C端场景“资产上翻”能力建设 (Q1)**
- **解决了什么问题**：在本地生活业务中，营销活动、商品详情等多种C端场景的搭建与迭代，往往需要研发人员在多个平台之间手动同步和调试物料（如 schema、组件代码），流程繁琐且易出错。“资产上翻”旨在打通本地开发环境与线上投放平台，实现物料的一键上翻和同步。
- **关键实现思路**：
    - **标准化资产协议**：定义了一套统一的资产包（Asset Package）规范，将不同场景的物料封装为标准结构，使其具备跨平台流转的能力。
    - **中心化资产管理**：搭建了一个中心化的资产管理后台，研发人员可以在此管理和版本化自己的物料。
    - **API & CLI 联动**：通过平台提供的 API 和命令行工具，开发者可以将本地的物料一键打包并上传至中心库，平台则自动将其同步至对应的线上投放系统，并刷新 CDN 缓存。

- **量化产出**：
    - C端场景物料的同步与调试时间从平均 **30分钟/次** 缩短至 **5分钟/次**。
    - 相关 MR：[feat: [](https://code.byted.org/ies/poi-zetton/merge_requests/269)[development task] 资产上翻mvp (1015616)](https://code.byted.org/ies/poi-zetton/merge_requests/269)

**2. 重点事项：Anywhere 任意门调试工具 (Q2-Q4)**
- **解决了什么问题**：前端开发过程中，经常需要在不同环境（BOE、PPE、线上）之间切换，以验证页面在特定数据或配置下的表现。手动修改 hosts、cookie 或使用代理工具不仅操作复杂，且难以覆盖所有场景（如依赖特定地理位置、用户身份等）。“Anywhere”工具旨在提供一个可视化的界面，让开发者可以“任意穿梭”于不同环境和场景，实现高效调试。
- **关键实现思路**：
    - **请求代理与动态规则注入**：工具内置了一个轻量级的请求代理服务。开发者在平台配置目标环境的 URL 和所需参数后，代理服务会动态生成转发规则，将本地请求无缝代理到目标环境，并根据配置注入 cookie、header 或修改请求参数。
    - **场景快照与复现**：支持将一套复杂的调试配置（如特定用户身份、圈选的实验组、请求参数等）保存为“场景快照”。其他团队成员可以一键加载快照，快速复现相同的调试场景。
    - **二维码在线预览**：针对移动端场景，平台可将本地开发页面生成一个临时的在线预览二维码。测试人员或产品经理用手机扫码即可在真实设备上体验，无需研发人员协助配置环境。

- **量化产出**：
    - 复杂场景（如需特定用户登录、命中 A/B 实验）的调试准备时间平均减少了 **80%**。
    - 打通了与QA团队的协作流程，非研发角色的问题反馈前置，减少了提测后的返工率。
    - 相关 MR：[feat: 表格支持任意门预览](https://code.byted.org/ies/poi-zetton/merge_requests/633), [feat: 任意门增加 /life/v1/dito/order/base/ 代理](https://code.byted.org/ies/poi-zetton/merge_requests/601)

**3. 重点事项：平台通用能力与体验优化 (全年)**
- **工作内容**：
    - **通用组件与布局**：构建了平台统一的侧边栏布局、卡片/表格视图切换、事件总线（EventBus）等基础组件，确保了平台内部体验的一致性。
    - **交互优化**：增加了如数据刷新、查询重置、表格懒加载、图片点击放大等一系列交互优化，提升了平台的可用性。
    - **健壮性建设**：引入了统一的请求库和错误处理机制，增加了异步任务取消功能，提升了平台的稳定性。

- **关键实现**：
    - 基于 Module Federation 实现了插件化架构，使得各功能模块（如资产上翻、Anywhere）可以独立开发和部署。
    - 利用 `useReducer` 和 `useContext` 封装了多个全局状态管理 Hook，简化了复杂页面的状态管理。

- **相关 MR**：[feat: scene-list 支持 cardView 和 tableView](https://code.byted.org/ies/poi-zetton/merge_requests/304), [feat: 任意门支持刷新数据](https://code.byted.org/ies/poi-zetton/merge_requests/658)

#### **方向二：业务支撑与问题修复**

**1. 重点事项：酒旅业务预订流程稳定性保障 (Q2)**
- **解决了什么问题**：线上反馈有用户在预订旅行社产品时出现失败的情况。经过排查，定位到原因为后端接口在某些特定条件下（如仅有成人或儿童数量时）的逻辑判断不完备。
- **关键实现思路**：与后端研发共同梳理了预订流程中的所有校验逻辑。在前端层面，调整了对预订人数（成人、儿童）和房间数的依赖判断，增加了兼容性处理，确保在部分参数缺失的情况下，流程依然能够正常进行或给出明确提示。
- **业务影响**：修复了特定场景下的预订失败问题，提升了酒旅业务的下单成功率。
- **相关 MR**：[feat: [](https://code.byted.org/life_service/life_trip_c_mono/merge_requests/1037)[development task] 旅行社预订失败 (1170446)](https://code.byted.org/life_service/life_trip_c_mono/merge_requests/1037)

**2. 重点事项：到餐/团购等业务功能迭代与优化 (全年)**
- **工作内容**：深度参与了到餐、团购、外卖等多个业务线的日常需求迭代。主要包括：
    - **新增功能**：支持了随心团、秒杀、惠享卡等多种营销活动的商品展示与筛选。
    - **查询与筛选优化**：重构了商品/订单列表的筛选功能，支持按业务身份、直播状态、产品类型等多维度进行组合查询。
    - **体验优化**：修复了商品价格展示错误、部分场景下样式错乱等多个线上问题，提升了用户体验。

- **业务影响**：确保了多个核心业务线的快速迭代和稳定运行，支撑了业务目标的达成。
- **相关 MR**：[feat: Inspect 支持随心团](https://code.byted.org/ies/poi-zetton/merge_requests/656), [feat: 秒杀活动](https://code.byted.org/ies/poi-zetton/merge_requests/588), [fix: 价格展示](https://code.byted.org/ies/poi-zetton/merge_requests/560)

### 四、结语

回顾2025年，是个人技术成长与业务理解深化的一年。从0到1构建 `poi-zetton` 平台的经历，不仅锻炼了独立负责复杂项目的能力，也让我对如何通过技术手段解决研发流程中的普遍痛点有了更深的理解。平台收获的积极反馈，是对技术价值最直接的肯定。
同时，持续深入到餐、酒旅等一线业务，让我始终保持对用户和业务的敏感度。技术最终要服务于业务，解决实际问题。在支撑业务快速迭代的过程中，也更能体会到平台化和工程化的重要性。
展望未来，希望能继续深化 `poi-zetton` 平台的建设，探索更多自动化、智能化的可能性，为团队带来更大的提效价值。同时，也会持续关注业务动态，以更前瞻的视角，用技术驱动业务发展。
