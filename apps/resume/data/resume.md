延迟 600ms→100ms 为述职中的前后对比，不与其他材料的 P95 口径混写。静态／动态转换成功率排除用户文件原因导致的失败；底层 PPT 转换由 WPS 提供。覆盖率、Bug 率及初始化代码行数为项目记录，不换算成未经测量的人天收益。Native 单需求人力投入 3→0.5 沿用原文单位，不换算成人天或推断需求工期；个人主导职责经用户最新确认。见 [述职](#s2)。

## 互动白板 · 技术介绍 {#board.body}

- **跨端架构**：主导移动端 SDK 从 Native 架构改造为跨端架构，将独立多端代码重构为一套代码三端共享。见 [述职](#s2)及用户确认。
- **协作与回放**：通过 RTS、Protobuf 同步数据，按元素／白板操作加锁；对比修改次数检查一致性，通过快照恢复回放跳转位置。
- **延迟优化**：减少 RTC 中心机房和 HTTP 中转，将边缘消息直接转发至白板服务。
- **课件服务**：使用 Puppeteer 加载 WPS Web SDK，提前触发 PPT 转换并检查原文件；优化服务架构及重试流程。以上见 [述职](#s2)。

## SDK 自动生成 · 技术介绍 {#sdk.body}

- **生成链路**：基于 Doxygen 提取 Native API 信息，结构化后生成 TypeScript；通过 Mapping 配置生成类、属性、方法和类型，配合适配代码统一 Android／iOS 对外 API。见 [旧简历](#s4)、[点播技术评审](#s27)。
- **跨端调用**：通过 IPC 传递 JSON，Native 侧反射调用 SDK。运行时设计用 instanceId 关联对象、callbackId 关联回调，并描述事件监听与派发。见 [运行时设计](#s29)。
